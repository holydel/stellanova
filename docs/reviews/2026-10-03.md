# Week review 1: 2026-09-30 to 2026-10-03

The first Saturday review of Stella Nova and pith: the code, the decisions
and the plans of the first week, with today's uncommitted work included.
Not committed; keep it, commit it, or delete it.

## Verdict

- **Both repos pass their own checks** on `windows-msvc` Dev with today's
  uncommitted work: the game's 4 ctests (27 doctest cases) and pith's 52
  ctests (118 doctest cases), Vulkan smoke tests under synchronization
  validation. No other preset or configuration was built in this review,
  so pith's new Android typing code was not compiled here; ADR 0011 says
  it builds but has not been tried on a phone.
- **The code is solid for its size and pace.** Reviewers kept finding the
  same things done right: bounds-checked readers, generational handles,
  deferred GPU destruction, a sound UDP handshake (SipHash cookie, padded
  requests, no state before the cookie returns), docs that match the code's
  numbers.
- **The weak spots are the edges:** the trust boundary of the public game
  server, failure paths (lost devices, full caches, refused fragments), and
  the decision layer (ADRs nobody accepted, a roadmap that became a
  changelog, a content plan ahead of the game it dresses).
- **Shipped but not committed:** Steam build 25670828 ("chat, /add_bots, no
  automatic waves online", uploaded 2026-10-02 11:46) and the Linux server
  binary built at 11:42 both contain today's uncommitted chat work. No doc
  records build 25670828; `steam.md`, `questions.md` and the roadmap know
  only 25669850.

## How it was checked

- 17 reviewers read one area each (sim, server and bots, client, today's
  diff, net, Vulkan, D3D12/WebGPU/shaders, OS, render/text/assets,
  shell/devlink/audio/platform, tools/build/scripts, core, both ADR sets,
  the plan, docs and hygiene, the public server's security); one built and
  ran both checks.
- Every high and medium finding went to independent verifiers told to
  refute it: 52 confirmed, 1 plausible, 10 refuted. Fifteen verifications
  failed (a session limit and a model safeguard); the network and server
  ones among them were re-checked by hand on 2026-10-03.
- Vendor claims in the content plan were checked against the vendors' own
  pages (below).
- **Not covered:** presets other than `windows-msvc` Dev, Android, the
  Deck, the live server (nothing was sent to it), fuzzing.

## The public server: fix before more strangers join

Anyone can reach it: UDP 27015, `wss://wos-observer.com/stellanova/ws`,
the site's footer, Steam keys. Each item below is cheap to trigger and
most are a few lines to fix.

| # | What | Where | Effect | Fix |
| --- | --- | --- | --- | --- |
| 1 | Input floats are not checked | `sim/src/protocol.cpp:91`, `server/src/server.cpp:211`, `sim/src/world.cpp:28,209` | One Input with a NaN turn makes every ship NaN within a tick (the clamp passes NaN; the bump code spreads it). The match stays dead until everyone leaves. | Refuse non-finite controls in the reader and clamp them; test it. |
| 2 | A second Hello leaves a ghost | `server/src/server.cpp:183` | `net::Disconnect` sends no event, so `Leave()` never runs: the Player and ship stay forever, the match never resets or idles, 32 ghosts hide every later player. | Ignore a repeated Hello, or call `Leave()` before every server-side disconnect. |
| 3 | The 33rd ship is never in a snapshot | `sim/src/protocol.cpp:418` | Snapshots take the first 32 slots; a player who joins after `/add_bots` fills them flies blind and sees "Connecting to..." forever (`client/src/flight.cpp:673`). | Cap players and refuse with a notice now; per-player snapshots with the own ship first later (the seed of interest management). |
| 4 | WebSocket frames are erased one by one from the front | `pith/net/src/websocket.cpp:306` | Quadratic: about 1 MB of empty frames costs seconds of CPU on the server's only thread; UDP players time out meanwhile. | Parse with an offset and compact once per pump; cap frames per pump. |
| 5 | A WebSocket peer that is closing has no timeout | `pith/net/src/websocket.cpp:501` | After `Disconnect` (which a wrong-version Hello triggers), a peer that stops reading keeps its slot forever and its input grows without bound toward the 256 MB cap. | A deadline for closing peers; stop reading once closing; cap `input`. |
| 6 | An empty UDP datagram ends the receive loop | `pith/net/src/socket.cpp:212`, `udp.cpp:152` | `ReceiveFrom` returns 0 for "nothing waiting" and for a 0-byte datagram, so a trickle of empty packets starves real players and handshakes. | Tell the two apart; skip empty datagrams. |
| 7 | Peers that never say Hello stay forever | `server/src/server.cpp:118` | Keepalives keep them alive; 64 such connections per transport lock everyone out. | A Hello deadline for connected peers. |
| 8 | Reassembly allocates 4 MB per peer up front | `pith/net/src/channel.cpp:320` | 64 peers times 4 MB of zero-filled buffers passes the unit's 256 MB cap: OOM kill, match over, repeatable. Several kills in quick succession hit systemd's default start limit and leave the service down. | A per-listener reliable size limit (the game needs a few KB from clients); grow buffers as fragments arrive; a global budget. |
| 9 | Names change at any time, without uniqueness | `server/src/server.cpp:221` | Anyone can take another player's name mid-match; zero-width and bidi characters pass `CleanText`. | Name once, before the join notice; unique within a match; drop format characters. |
| 10 | One log line per malformed datagram | `pith/net/src/udp.cpp:388` | A connected peer can push journald to its rate limit, which then drops the server's own lines on the shared host. | Rate-limit that warning per peer. |
| 11 | `/waves on` survives the restart | `server/src/server.cpp:253` | After one visitor turns waves on, every later empty-server restart keeps them. | Keep the started `MatchDesc` and restore it in `Restart()`. |

Also: the systemd unit that provides the hardening exists only on the
production machine (not in either repo), and nothing alerts when the
service is OOM-killed or stays failed.

## Other confirmed defects

### The game

- **Alt+Enter is also Enter** (`client/src/menu.cpp:209`): toggling
  fullscreen starts the selected menu item or opens the chat.
- **A server's rock radius is used as a piece count**
  (`client/src/flight.cpp:589`): a hostile or buggy server crashes or
  freezes the client on the first broken rock. `--server` takes any address.
- **The Steam name races the connection** (`client/src/flight.cpp:361`):
  Name is sent once at Connected, while Steam's name is still empty, so
  online players with Steam join as "Pilot N".
- **Pads, the mouse and touch keep flying while the chat is open**; only
  keys are muted. Intended? On the Deck the pad is the only input.

### pith

- **No backend handles a lost device** (`rhi/src/vulkan/vk_swapchain.cpp:612`,
  `rhi/src/d3d12/d3d12_swapchain.cpp:376`): every tick fails and dumps a
  fault; a failed submit leaves a fence that blocks forever.
- **Upload staging eats the frame's transient ring first**
  (`rhi/src/vulkan/vk_resources.cpp:169`): a frame with many uploads leaves
  the app's draws without their frame block.
- **The pipeline cache is never written on Android**
  (`rhi/src/vulkan/vk_device.cpp:728`): it is saved only on DestroyDevice,
  which Android never reaches, and read back without an integrity check.
- **A failed swapchain recreate leaves null framebuffers**
  (`rhi/src/vulkan/vk_swapchain.cpp:304`), and recreation never runs under
  validation in any test.
- **D3D12:** pending uploads are keyed by slot, so destroy-then-create lands
  old data in the new resource (`d3d12_resources.cpp:476`); each bind group
  with a sampler takes 8 of 2048 sampler descriptors, so 256 such groups at
  most (`d3d12_backend.h:28`).
- **The reliable channel acknowledges before it accepts**
  (`net/src/channel.cpp:193`): a fragment refused for the 4 MB cap is never
  resent and the stream stalls silently. Not reachable by the game today.
- **Losing focus keeps mouse buttons and fingers down**
  (`os/src/common/events.cpp:533`).
- **The text atlas's growth failure path pops a page it never pushed**
  (`render/src/text.cpp:327`).
- **F1 traps the keyboard** (`debug_ui/src/debug_ui.cpp:138`): with keyboard
  navigation on, a focused ImGui window takes every key, F1 included.
- **The first frame waits for the audio device** (`client/src/main.cpp:169`):
  device open time (65 ms to seconds) sits inside the 2-second budget.
- **Devlink reads a line without a size limit** (`devlink/src/socket.cpp:289`).
- **The palette test asserts half its line** (`tools/pith/CMakeLists.txt:34`):
  CTest splits the regex at the `;`.
- **A failed REQUIRE does not stop a test** (`tests/test_main.cpp:15`): with
  no exceptions, a regression becomes a crash instead of a report, which on
  the Deck and Android comes back as an exit code only.
- **Captures stop silently past 262,144 events per thread**
  (`core/src/profile.cpp:20`): the documented 6000-frame run uses 94%. Each
  short-lived worker thread that records a scope pins 8 MB
  (`core/src/profile.cpp:75`); the glyph worker starts one per job.

## Decisions, plans and docs

- **Steps 47-54 are not a milestone.** They have no "done when", no place in
  the milestone list, and they pull M1.7 ahead of M1.4-M1.6 without a
  recorded trade-off. The content plan sizes ships from today's 40 m camera
  and plans icons for modules that do not exist, while the vision's first
  rule is readable battles of up to 500 ships, a view nobody can look at yet.
- **Nobody has accepted the decisions.** All 11 game ADRs and 22 of pith's
  36 are "Proposed" (the other 14 were marked Accepted by the agent), including brainCloud with Edgegap (0005), rewards only
  from our servers (0002) and the netcode (0003). Accepted ADRs 0023 and
  0024 were edited in place.
- **Review debt.** About 43k lines of engine C++ and 7k of game code went in
  with 37 commits over three days, most in large commits and an overnight
  run. How much of it a person has read is a question for the developer.
- **XR and the scene graph** are the roadmap's two named engine goals and
  got none of the 46 steps; pith ADR 0001 says stereo and multiview are
  "first-class from the start", but nothing in the RHI, frame block or
  shaders knows about views.
- **ADRs 0010 and 0011 disagree on compatibility:** "one protocol version,
  updated together" against "within version 3 old and new still play
  together". The second Steam build hides the cost, if it is live.
- **The vision contradicts itself on fleet size:** 4-7 ships in the pitch
  and M1.4, 1-5 in the skirmish row.
- **The roadmap's milestone list stopped at M1.1:** M1.3 and M2.1 are done
  but unmarked, M0.3-M0.5 carry no Done, "Later in Phase 0" still plans an
  sdl3 backend, and by the list XR (M1.2) is next.
- **The same facts are told two or three ways:** the Steam build is and is
  not live (`steam.md`, `questions.md`), and a phone is and is not
  connected (`questions.md`, roadmap step 45). ADR 0010 still documents
  `--no-bots`.
- **Third-party notices:** the Steam builds and the public web page ship
  FreeType, HarfBuzz, msdfgen, miniaudio and stb (and volk natively)
  without their notices; FreeType's license requires a credit in the
  documentation.
- **Uncompressed packs** (pith ADR 0006 has no code): the game's own pack is
  9.9 MB (Dev), and generated content will grow it; on the web and phones
  the download, not the code, decides the 2-second goal.

## Fixed the same day

After the developer's answers (recorded in `docs/vision.md`,
`docs/roadmap.md` steps 55-61, and both ADR indexes, where every ADR now
has the developer's verdict):

- **The public server** (ADR 0012, pith ADR 0036's addendum): items 1-11
  above, each with a test. Controls travel as 1/127 steps and every float
  from the wire must be finite; a repeated Hello is ignored; at most 16
  players, the rest refused with a reason; each player's snapshot starts
  with its own ship, then the nearest; peers that never say Hello go after
  10 s; WebSocket frames are parsed in linear time, closing peers time out,
  input is bounded; empty UDP datagrams are skipped; reassembly memory
  follows what arrived, with the game's limit of 2 KB a message; datagrams
  are acknowledged only once taken; names are unique and cleaned; the
  waves go back to the start-up setting; malformed datagrams are logged
  once per 10 s; controls that stop coming let go after half a second.
- **Own-ship prediction** (protocol 4): the developer's main complaint as a
  tester.
- **The Steam name race** and **Alt+Enter as Enter** (the game).
- **Chat in phone browsers** (pith's web backend): a hidden text field,
  checked in desktop Chrome; not yet on a phone.

Still open from this review: lost devices on every backend, upload staging
sharing the transient ring, the Android pipeline cache, D3D12's slot-keyed
uploads and sampler blocks, focus loss keeping buttons down, the text
atlas's failure path, F1 trapping the keyboard, the first frame waiting for
audio, devlink's unbounded line, the palette test's regex, REQUIRE without
exceptions, the profiler's buffers, a client trusting a server's numbers,
third-party notices, per-server memory budgets and a per-peer message rate
on UDP (found while fixing the rest), and pith's public-readiness items.
